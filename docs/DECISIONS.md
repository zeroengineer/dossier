# Decisions

Small decisions made while building Dossier. Each entry: decision, reason, cost if wrong.

## 2026-11-23 (planning)

- **Code is organisation-agnostic.** All organisation data, assets, strings, clause bodies and numbering patterns live in a workspace (`DOSSIER_HOME`), never in `src/` or git. Reason: Dossier is a public app. Cost if wrong: one extra indirection for single-company use.
- **Discovery is committed redacted.** `docs/DISCOVERY.md` replaces registration ids, bank details, phone numbers and salary figures with placeholders; the full copy lives in the private workspace. Reason: the brief asks for discovery in the repo, and the repo is public. Cost: readers of the repo see placeholders instead of real values.
- **`node:sqlite`** (built into Node 22.23, SQLite 3.53 with FTS5) over `better-sqlite3`. No native build. Fallback documented if the experimental API changes. Run with `--no-warnings=ExperimentalWarning`; WAL mode because the HTTP server and MCP process share the file.
- **Fastify + server-rendered HTML**, no bundler. One deployable, few dependencies; every screen is form in, HTML out.
- **Template = folder** with `template.json` + `pdf.js` (+ `blocks.js` or `body.md`). Workspace templates override built-ins by id.
- **Flow documents share one block model** (PDF, HTML, Markdown). The absolute-positioned invoice family keeps hand-written `pdf.js` and `html.js`.
- **Markdown-bodied templates (MoU, agreement):** the filled source markdown is the Markdown rendition verbatim; PDF/HTML are rendered from its parsed blocks (user decision).
- **HTML rendition is a web rendition**, same fonts and metrics, not a line-for-line facsimile of the PDF.
- **Numbering = pattern engine + series config.** Shared counters (invoice / debit note / receipt) are configuration. Legacy number conflicts are flagged, not rejected.
- **Shipped assets are only OFL fonts (Manrope) and generated neutral placeholders** at the pixel sizes the layouts expect. Real logos, seals and signatures are workspace files.
- **Figtree is missing** from the legacy folder, so portfolio and IEEE-header layouts are out of the initial scope.
- **Dates stored ISO**; display formats come from the workspace locale, with per-template overrides.
- **PDF determinism:** document info dates are pinned (fixed epoch in tests, version timestamp in production) so pdfkit output is byte-stable.
- **Text extraction with `pdfjs-dist` legacy build**, not `pdf-parse` (a heavier wrapper around an older pdfjs).
- **Work on `main` in the new repo.** The repo was empty and the brief asks for commits after each feature; no other branch exists.
- **Pushes deferred** until GitHub auth is configured on this machine (user decision). Commits are made locally after each feature.
- **Implementation by Opus 5.5 subagents**, one feature per agent, each reviewed before the next (user request).
- **MIT licence** for code (public app); Manrope stays under OFL.

## 2026-11-23 (workspace loader)

- **Brand inheritance merges raw JSON, then validates.** A child `brand.json` may be partial; errors are reported against the child file. Arrays replace, objects merge. Asset paths resolve in the child folder first, then up the parent chain. Reason: an LLP or product brand usually differs only in name, ids and logo.
- **Signatories get an optional `signatureLarge`** next to `signature`, and `brandAsset` a `signature-large:<id>` key, because the letter family draws a differently proportioned "authorised sign" image (5914×4873 placeholder) than the invoice family (1024×406). It falls back to `signature`, then to the large placeholder.
- **`series.json` `scope` defaults to `brand+year`**, the scope of every pattern containing `{YYYY}`; `counter` defaults to the series' own id.
- **`hierarchy.topLevel` must have exactly 10 names** when given, matching the ten top-level folders of the tree view.
- **Placeholder images are drawn from SVG paths only** (no `<text>`), so rendering does not depend on system fonts and the committed PNGs are reproducible.

## 2026-11-23 (database)

- **Entity ids are integers; document ids are text `DOC-000001`** from the `sequences` row `doc-id` (6-digit zero padding, more digits after 999999). Reason: entities are internal rows, document ids are user-facing and stable.
- **`documents` carries both `issuing_brand_id` (workspace brand) and `issuing_entity_id` (entity row).** The brand drives rendering; the entity drives the hierarchy and search.
- **`document_relations.to_doc` has no foreign key** because `generated_from` points at a template (`template:<id>@<version>`, enforced by a CHECK). Triggers give document targets the same protection as a foreign key and delete incoming relations when a document is deleted.
- **One rendition per kind per version** (`UNIQUE(version_id, kind)`); a stamped or watermarked file is a new version (rule B5.7).
- **Money needs a currency and must be an integer** (`CHECK`), party needs a party type, new documents default to `Draft` / `Internal`.
- **Extracted text lives only in `document_text`**, not on `renditions`; the FTS5 index (`documents_fts`) arrives with search in a later migration.
- **Nested transactions join the outer one** (no savepoints): an error anywhere rolls back the whole unit. Transaction callbacks must be synchronous. Errors thrown by post-commit listeners never reach the writer (the write is committed): they are emitted as `listenerError` on `repo.events`, or logged to stderr when nobody listens. The wrapper tracks its own transaction and closed state rather than relying on newer `node:sqlite` properties. Post-commit events wait for the outermost commit even when it was opened with `db.withTx` directly; per-table write versions are bumped when the transaction ends, on rollback too, so a memo built from uncommitted rows is never trusted.
- **One name normalisation: `normaliseName(name)`** (`src/domain/canonical.js`, re-exported by `src/services/entities.js`; `canonicalKey` is the same function): NFKC, lower case, curly quotes and dash variants unified to `'`/`"`/`-`, punctuation other than `&`, `'`, `-` replaced by a space, whitespace collapsed. Used for `entities.canonical_key`, `entity_aliases.alias_key`, lookups and seed validation. Names and aliases must keep at least one letter or digit.
- **Entity names are unique per kind across names and aliases.** `upsertEntity` without an id updates the entity whose canonical key matches (keeping its display name); a name or alias owned by another entity of the same kind is `ENTITY_DUPLICATE` with `existingId`, unless `aliasOf` names that entity. Renaming by id keeps the old name as an alias. Aliases are only ever added; `attrs` are shallow-merged with `null` deleting a key. Unchanged upserts write no audit row and emit no event.
- **`entity:changed` payload is `{ ids: number[] }`** (one id for entity writes, both ends for relation writes).
- **Seeding never overwrites** existing entities' names, attrs or brand; it only adds missing entities, aliases and relations, so it is safe to run repeatedly.
- **Service errors are `DossierError(code, message, details)`** (`src/errors.js`) with UPPER_SNAKE codes: `INVALID_INPUT`, `ENTITY_NOT_FOUND`, `ENTITY_AMBIGUOUS` (a name matching several kinds; `details.candidates`), `ENTITY_DUPLICATE` (`details.existingId`).
- **Brand rows are synced on every `openContext`**, written and audited only when the legal name or config hash changed; rows of removed brands are kept for the documents that reference them.

## 2026-11-23 (vault core)

- **Blob files are written before the transaction** (`storeBlobFile`: temp file + rename, skipped when the file exists, rewritten when missing); only the `blobs`/`renditions` rows are inserted inside it (`recordBlob`). File IO never holds the write lock shared by the HTTP server and the MCP process. A rolled-back transaction can leave an unreferenced blob file; it is harmless because files are content-addressed and reused by the next identical upload.
- **Files are served only through `readRendition(ctx, documentId, { versionNo?, kind })`**, which checks the document's sensitivity. `readBlob` / `blobPath` are internal (no access check): one blob can back a Public and a Restricted document at once, so a sha-only check can never be right.
- **A document without a current version always takes the new version as current**, even with `makeCurrent: false`.
- **Originals are immutable by API shape:** no exported function updates or deletes a rendition; a stamped file is a new version. No database trigger was added (the services are the only writers).
- **Status may be set freely at creation** (imports of historical documents can start as Paid); after that only the transition table applies. Setting the current status again is a no-op. `updateMetadata` refuses `status`.
- **Users cannot create or move a document above their own clearance** (`FORBIDDEN`), so nobody files what they cannot read. `getDocument` of a document above clearance is `FORBIDDEN` (not `DOCUMENT_NOT_FOUND`); related documents above clearance are left out of `relations`.
- **`partyType` is inferred from the party entity's kind** (company -> Company, group_entity -> GroupEntity, person, client, vendor, product) when not given; changing the party without a type re-infers it. The party column is not copied into `document_entities`; `entities` holds the extra roles only.
- **The secret scanner applies to every upload**, not just Restricted documents: extensions `.pem`, `.key`, `.env`, file names `.env` / `.env.*`, and the markers `-----BEGIN` / `PRIVATE KEY` in the bytes or extracted text (`SECRET_REJECTED`, nothing stored).
- **A version needs at least one rendition**; one per kind. Default MIME types per kind when none is given. Number conflicts are re-evaluated when `updateMetadata` changes the series or number; flags on other documents are left as they are.
- **Display file names** drop empty segments and slug each segment: accents stripped, spaces removed, `/ \ _ : |` become `-`, other non-letter/digit characters dropped. The `original` rendition keeps its own file extension.
- **Error codes added:** `DOCUMENT_NOT_FOUND`, `VERSION_NOT_FOUND`, `RENDITION_NOT_FOUND`, `BLOB_NOT_FOUND`, `BRAND_NOT_FOUND`, `FORBIDDEN`, `INVALID_STATUS_TRANSITION`, `SECRET_REJECTED`. Event `document:changed` carries `{ ids: string[] }`.

## 2026-11-23 (upload and text extraction)

- **`uploadFile` is async** (pdfjs is promise-based); `extractText` never throws: unknown types, encrypted and broken PDFs give empty text.
- **An upload's renditions share one blob:** `original` always, plus `pdf`/`html`/`md` when the extension is `.pdf`, `.htm(l)`, `.md`/`.markdown`. Extracted text is stored once, against the `original` rendition, and only when non-empty. PDFs record `page_count` on both renditions.
- **`deduped`** is true when a `blobs` row with the file's sha256 existed before the upload (checked inside the upload transaction).
- **Document creation and the first version are one transaction**, so a failed version leaves no empty document. The blob file is written before it (rule above); `addVersion` then only finds the file present.
- **With `meta.documentId` only `note` and `makeCurrent` are accepted**; metadata changes go through `updateMetadata`. Without it, `title` defaults to the file name minus its extension.
- **The secret check runs twice on upload:** on name and bytes before extraction, then on the extracted text (catches markers hidden by HTML entities or PDF encoding).
- **`warnings: ['NUMBER_CONFLICT']`** is returned whenever the resulting document carries the conflict flag. Client file names are cut to their last path segment.
- **pdfjs runs with `verbosity: ERRORS`** and its fake worker (`GlobalWorkerOptions.workerSrc` set to the legacy worker module) so tests stay quiet.

## 2026-11-23 (hierarchy view)

- **Routes are `{ top, leaf }`.** Most types are party-relative (leaf inside the party's folder); a few are fixed to a top-level folder: Board Resolution and certificates of incorporation/registration -> `01 Company/<leaf>`, Bank Statement / Tax Return / Ledger -> `06 Finance/<FY>/<leaf>`, Template -> `07 Templates`, Reference -> `08 References`. Workspace `hierarchy.routing` values are a leaf name or `<top-level name>[/<leaf>]` (current or default top-level name). Reason: one string format covers both kinds of route.
- **Unknown document types go to the party's folder with leaf `Other`** (for clients: business line / client / [engagement] / Other). Documents without a party (or with a party-relative route and no party) are filed under `01 Company`, since the company is the implicit party of its own papers.
- **Client business line:** `documents.business_line_id`, else the client's `belongs_to_business_line` relation (first by name if several), else `Unassigned`. A client can appear under two business lines when its documents name different ones.
- **Engagement level** is decided per client over the documents placed in its folder (visible to the user, not Restricted): shown only with more than one distinct engagement; documents without one then go to `General`.
- **Restricted documents are listed flat in `10 Restricted`**, and that folder is omitted for users not cleared for Restricted (the folder's existence tells nothing). Other top-level folders are always present, even when empty.
- **Finance folders use the Indian financial year** (April-March, `FY 2026-27`); undated finance documents go to `Undated`. People documents sit under `02 People/<person>/<leaf>`, group entities under `09 Group Entities/<entity>/<leaf>`, company documents directly under `01 Company/<leaf>` (no company-name level).
- **Node ids** are the top-level slot number (`03`, stable when folders are renamed) followed by lower-case slugs of folder names (`03/events-line/demo-retail-llp/invoices-and-receipts`). When siblings' names slug alike, a named folder (Unassigned, General, a leaf) or else the lowest entity id keeps the plain slug and the other entities get `-<entity id>`, so creating an entity never renames an existing node (entity ids only grow). Residual case: an older entity whose first document arrives after a newer clashing one takes the plain slug over. `''` is the root. `getNode` of an unknown id is `NODE_NOT_FOUND`.
- **Display name per document** follows the file-name rule with the extension of the current version's best rendition (pdf, else original's extension, else html, md); documents sort by display name, folders by name.
- **The tree is built in memory on each call** from three queries (documents, current renditions, business-line relations) and a pure `assembleTree(items, { hierarchy, clearance })`; caching comes with the cache layer.
- **Each top-level folder has a closed B3 leaf set** (`TOP_LEAVES` in `src/domain/routing.js`): Company {Legal and Registration, Board and Governance, Banking and Payments, Compliance and Tax, Company Profile, Brand Assets}; People {Onboarding, Employment, Exit}; Clients {Proposals and Pricing, Agreements, Invoices and Receipts, Settlements and Statements, Deliverables and Correspondence}; Vendors {Agreements, Invoices Received}; Products {Marketing, Specifications, Pricing, Brand Assets, Design Source}; Finance {Bank Statements, Tax Returns, Ledgers and Reports}. Group entities, Templates and References have no B3 leaf set and accept any leaf. A default route's leaf is first translated per folder (`LEAF_MAP`: Products map Proposals and Pricing -> Pricing and Agreements -> Specifications; Vendors map Invoices and Receipts -> Invoices Received), then becomes `Other` if still outside the set (a Person's NDA -> `Other`, a Company or party-less Invoice -> `01 Company/Other`). Workspace routing overrides keep precedence and are used as given.
- **Only sensitivity places a document in `10 Restricted`.** A `hierarchy.routing` value naming the Restricted folder (current or default name) is a workspace validation error at `hierarchy.routing.<type>`; `routingConfig` also ignores such a value if handed one directly.

## 2026-11-23 (search)

- **One FTS5 row per document** in `search_index` (`porter unicode61`), rowid = the numeric part of the document id so a row is replaced by rowid. Columns: `title` = title + type, `number` = document number + id, `parties` = names and aliases of the party (`party_id` and `document_entities` role `party`), `body` = extracted text of every rendition of the current version, identical texts once. Signatories and named people are not in `parties`: they reach documents through expansion.
- **Reindexing happens in the writer's transaction**: `documents.js` reindexes every id it reports as changed (create, metadata, version, current version, status, relations, supersede); an entity whose name or aliases change reindexes the documents that have it as party or through `document_entities`. A delete trigger removes the row of a deleted document. When migration 002 is first applied, `openContext` indexes existing documents once; `dossier reindex` rebuilds everything.
- **Query handling**: control characters removed, words split on whitespace, inner `"` dropped, each word quoted (so `OR`, `NEAR`, `*`, `:`, parentheses are plain words), words without letters or digits dropped; all words must match. No prefix search in FTS (porter stems and prefixes do not mix); document numbers have their own prefix match, which needs two characters and no spaces.
- **Ranking tiers**: exact number/id (case-insensitive) > number prefix > metadata (match restricted to title/number/parties) > text; inside a tier by `score` = negated bm25 with weights title 10, number 10, parties 5, body 1 (0 for number matches without an FTS match). Only text hits carry a snippet (body column, `[` `]` markers, 12 tokens).
- **Entities**: `findEntities` substring match on names and aliases, at most 10. Expansion roles: party (incl. `documents.party_id`), signatory, named; contact and issuer are not expanded.
- **Filters apply to related documents too** (types, status, partyId, from/to and sensitivity), so a filtered search never returns a document outside the filter. `limit` (default 20, max 200) caps hits and related separately. Related order: documents linked to hits (hit order, then relation order), then entity documents (newest first); each document once, never repeating a hit. Unknown search options are `INVALID_INPUT`.

## 2026-11-24 (numbering)

- **Pattern rules:** tokens `{YYYY}` `{YY}` `{MM}` `{FY}` `{BRAND}` `{CLIENT}` `{CODE}` and exactly one counter `{#…}`; any other `{…}` (e.g. `{PREFIX}`) is `SERIES_PATTERN_INVALID` and a workspace load error at `series.json <i>.pattern`. Prefixes are literal text. `{YY}` parses back as 20YY. Numbers are parsed case-sensitively.
- **Counter keys** in `sequences` are `num:<counter>[:<BRAND>][:<year>][:<CLIENT>]` (prefix keeps them apart from `doc-id`); year is `2026` or `FY2026-27` (YYYY wins over FY; neither -> calendar year of the date). `{BRAND}` uses the brand id; brand defaults to `workspace.defaultBrand`, an unknown brand is `BRAND_NOT_FOUND`.
- **Shared counters:** `counter` must name a series that owns its counter (no chains), and a sharer must have the owner's `scope` and year basis (validated at load, otherwise the counter would silently split); the counter starts at the owner's `start`.
- **Input checks:** dates must be real calendar days (`2026-02-31` is `INVALID_INPUT`); an explicit `fy` must be `YYYY-YY` with consecutive years, else `INVALID_INPUT`. Adjacent code tokens joined by `-` parse greedily (documented on `parseNumber`).
- **Values:** `{BRAND}`/`{CLIENT}`/`{CODE}` are uppercased; whitespace/`_`/`-` runs become one `-`, other characters are dropped. Empty after that -> `NUMBER_VAR_MISSING`. Dates are `YYYY-MM-DD` strings taken literally (no time-zone shift) or `Date` objects read in local time; `allocateNumber` defaults to today (local).
- **Missing vars are checked before a value is taken**, so a failed allocation consumes nothing even outside a transaction. `allocateNumber` runs in `ctx.repo.tx` (joins the caller's transaction; rolls back with it). Allocations are not audited (the document that receives the number is); `seedCounter` writes a `sequence.seed` audit row when it moves a counter.
- **`seedCounter(ctx, seriesId, vars, next)`** takes `{ date | year | fy, brandId | brand, client }` and never moves a counter back (nor below the start). It has no date default: a year-scoped seed without a year is `NUMBER_VAR_MISSING`. `registerExisting(ctx, seriesId, number, { brandId?, date? })` parses with the series pattern (`NUMBER_UNPARSEABLE` if it does not fit) and seeds to `seq + 1`.
- **`interpolate()` keeps unresolved all-uppercase names** (`{YYYY}`, `{CODE}`, …) as written; lower/mixed-case misses still print empty.
- **Error codes added:** `SERIES_UNKNOWN`, `SERIES_PATTERN_INVALID`, `NUMBER_VAR_MISSING`, `NUMBER_UNPARSEABLE`.

## 2026-11-24 (pdf render primitives)

- **Primitives live in `src/render/pdf/`** (`profiles`, `document`, `images`, `format`, `letterhead`, `footer`, `text`, `tables`, `signature`, `watermark`, re-exported by `index.js`). Every helper takes `ctx` (`{ doc, profile, brand, ws, palette, fmt, assets, t, interp, contact, pageNumber }`); all constants are defaults that options override, colours come from the brand palette, printed strings from the brand or the caller. Reason: one port of the legacy helpers serves every template.
- **Ported with the legacy arithmetic and call order.** Checked against the legacy offer letter and invoice scripts run outside the repo with the same assets and strings: all text items identical (pdfjs transforms, unrounded) and pages pixel-identical at 72 and 150 dpi. Only extra redundant colour operators differ in tables.
- **`getProfile(id, brand.layoutProfiles)`**: overrides are per profile id, numeric keys validated, `CW` always recomputed. Invoice carries `CP: 0`.
- **Transparent images are embedded by Dossier, not pdfkit.** pdfkit splits an alpha PNG on an asynchronous inflate, so object numbers depended on which image finished first and renders were intermittently not byte-identical. `loadImage` pre-splits colour and alpha planes (deflated) and `placeImage` writes them synchronously as image + SMask; opaque images still go through pdfkit's PNG path. Each image is embedded once per document and reused on every page (the legacy scripts re-embedded the logo per page), so files are smaller with identical pixels.
- **Async where images are involved**: `attachLetterhead` (prepares the logo once, sharp height 80) and `drawSignatureBlock` return promises; `drawLetterhead` needs a prepared logo. Images are sized from the prepared image's real dimensions.
- **Hooks**: `createPdf` sets `Rotate 0` and counts pages on `pageAdded`; `onPageAdded` hooks (letterhead) are removed by `drawFooters`, `drawWatermark` and `finalizePdf`, so post-passes cannot cascade headers.
- **Footer slots default to `brand.footer`**; `{page}`/`{pages}` and brand placeholders are filled, empty slots skipped. `centerStyle: 'caps'` upper-cases the text (SemiBold 7.5, spacing 1.2, muted).
- **Options use `??`, not the legacy `||`**: an explicit `0` (e.g. `moveDown: 0`) is honoured.
- **Tables** take per-column `font`/`color`/`padX`/`padRight`, `row.height: 'auto'` and break pages with a repeated header; a header that would be alone at the bottom of a page moves with the first row.
- **Watermark is vector text** (selectable), drawn per buffered page with the MoU geometry (centred on `PW/2`, rows `PH/2 ± PH/4.5`, -30°), replacing the legacy rasterising `watermark.js`.
- **Formatting**: money takes minor units (`fmt.money(minor, { space, decimals })`); dates parse `YYYY-MM-DD` literally; patterns support `Do` (31st). Amount in words uses Thousand/Lakh/Crore with crores recursing (`One Lakh Crore`), zero is `Rupees Zero Only`, paise-only amounts read `Fifty Paise Only`. Words come from `locale.currencyWords` (`major`, `minor`, `suffix`).
- **`test/helpers/pdfText.js`**: `extractItems` reports `y` as the top of the line box (baseline minus ascent, i.e. the `y` given to `doc.text`) plus `baseline`; pdfjs merges same-font runs on a line, so justified lines are checked by their extent. `extractImages` reports placed image boxes. Geometry snapshot JSON is committed; `UPDATE_SNAPSHOTS=1` rewrites it.

## 2026-11-24 (generator)

- **Peek, render, then allocate-and-verify in one transaction.** The number must be printed inside the PDF, rendering is async, and `repo.tx` is synchronous. `generateDocument` peeks the series' next number, renders every rendition with it outside any transaction, writes the blob files (content-addressed, harmless if unused), and then in one transaction allocates the number and checks it equals the peeked one before creating the document, version 1 (addVersion finds the blob files already written and only inserts rows), relations, entities and the `document.generate` audit row. If another writer took the number meanwhile, the transaction rolls back (the counter is not consumed) and the document is re-rendered with the new peek, up to 3 attempts, then `NUMBER_CONTENDED`. Reason: a number is never allocated without a stored version, and no async work runs inside a transaction. Rejected: allocating and creating an empty numbered document first, then rendering and adding the version in a second transaction, which leaves a numbered document without a version if rendering fails.
- **Only Draft documents regenerate freely** (review ruling, overriding the brief's "status resets to Draft"). A Sent, Signed or Paid document is `STATUS_LOCKED` with a hint to supersede it, unless `force: true`, which resets it to Draft (or keeps its current status when `status` names it) through `resetStatus` in `documents.js`, audited as `document.status` with `reason: 'regenerate', force: true`. On regeneration `status` may only be Draft, or the current status with `force`; at creation any status except Superseded. Superseded documents cannot be regenerated; only the same template id and the same issuing brand can regenerate a document (another `brandId` is `INVALID_INPUT`). The number and series are kept; the other metadata (party, date, amount, title, template version, entities) are refreshed from the new input.
- **Per-series in-process queue.** Generations of one series in one process (keyed by the db connection and series id) run peek, render and allocate one after another, so the web server never re-renders for its own requests; the peek-verify retry and `NUMBER_CONTENDED` only cover other processes. Regenerations take no number and are not queued.
- **DRAFT only when `draft` is true.** Final renditions pass the number or null (`''` for body.md), so an unnumbered final document never says DRAFT; templates use `env.draft` as the switch.
- **Input checks before rendering**: `canonicalJson` refuses values JSON cannot carry (BigInt, functions, symbols, non-finite numbers, Maps and other class instances) with `INVALID_INPUT`; declared relation targets must exist, be visible to the user and not be the document itself.
- **Signatory lookup** ignores only `ENTITY_NOT_FOUND`; an ambiguous signatory name is an error, not a silent skip.
- **Preview files are rewritten on every preview**, at a path keyed by the token (template hash + canonical input + brand hash). The token does not include today's date, so serving a cached file could show a stale `today` default; previews are cheap, so they are always re-rendered.
- **Party, signatory, issuer.** The party is the first entity-valued field of kind `partyKind`. Brand signatories are configuration, not entities: the `signatory` link goes to a person entity with the signatory's name when one exists. The issuer is the `company` entity linked to the issuing brand. Numbering vars: `{CLIENT}` from the party's `attrs.code`, `{CODE}` from `values.numberCode` (else `values.code`).
- **Extracted text** of every rendition (PDF via pdfjs, HTML stripped, Markdown as is) is stored with the version so search finds generated documents by their content.
- **Error codes added:** `FIELDS_MISSING`, `FIELDS_INVALID`, `NUMBER_CONTENDED`, `STATUS_LOCKED`.

## 2026-11-24 (invoice family templates)

- **One frame, three configs.** `src/render/pdf/invoiceFrame.js` builds a model (every printed string resolved from values, params and brand) and draws it; HTML and Markdown render the same model. The templates differ only in `template.json` params (labels, columns, row height, bank or acknowledgement panel, `frame` style overrides). Reason: the legacy invoice, debit note and receipt scripts are one layout with small edits.
- **Own table loop, not `drawTable`.** The legacy table has per-column quirks (header widths differ from cell widths, only the description has a line gap, the receipt starts descriptions over 40 characters at +6 instead of +12, one rule under the whole table). Reproducing them in `drawTable` would have needed options used nowhere else.
- **Checked against the legacy scripts** run in a temp directory with fake strings substituted: invoice (CGST), no-tax 105 pt row, IGST, auto row height with Bold description, debit note and receipt all give identical text positions, sizes and fonts and pixel-identical pages at 100 dpi. The only difference is the brand's tax labels (`CGST (9%)` where the oldest script computed `CGST (9.00%)`).
- **Tax rounding**: tax on the subtotal, total tax rounded half up, split over the rates with the odd paisa on the last line (legacy 17.46 / 17.47). Rejected: rounding each rate separately (two half-up roundings can disagree with the total tax by a paisa) and per-item tax.
- **Upper-casing** of the from name, the "FOR …" line and the signatory name and title follows the legacy look; brands keep their names in normal case.
- **Relation fields may hold a list of ids** (a receipt pays several documents); each id becomes one relation.
- **Shared module outside the template folders** (`src/render/invoiceTemplate.js`): editing it does not change a template's registry hash; template versions must be bumped when the frame changes behaviour.

## 2026-11-24 (letter family templates)

- **Blocks, not a frame.** The offer letter, internship offer, certificates and relieving letter are block documents (`blocks(values, env)`) drawn by `renderBlocksPdf`; only the page-1 head of the offer family (`letterOpening`) and the certificate head (`certificateHead`) are custom blocks, because they sit at absolute positions under the letterhead. Shared builders live in `src/render/letterTemplate.js`; the template folders hold the wording (`template.json` params) and, for the offer letter, the salary annexure. A shared module is not in a template's registry hash: bump the template versions when it changes behaviour.

## 2026-11-24 (web UI)

- **Server-rendered pages, one `html` tag.** `src/web/html.js` escapes every interpolation; trusted markup is only nested `html` results or an explicit `raw()`. Views are one module per page (`src/web/views/*.js`), routes grouped by resource (`src/web/routes/*.js`), `src/server.js` only wires plugins, hooks and routes. Routes call services only; the two new read helpers live in services: `readBlobForUser` (documents) and `formFields` (fields).
- **One context per server.** The process opens one workspace as `DOSSIER_USER`; there is no login. Multi-user access needs a reverse proxy with authentication and is out of scope.
- **CSRF without tokens.** The server binds to 127.0.0.1 and rejects non-loopback `Host` headers (DNS rebinding). State-changing requests need an `Origin` (or `Referer`) whose host equals `Host`; without either, only requests a cross-site page cannot forge without a preflight pass (JSON body, non-POST method, `X-Dossier-Client` header). `Origin: null` is refused. Rejected: synchroniser tokens (state per form for a single-user local tool), SameSite cookies (no cookies at all).
- **Files only through documents.** `/documents/:id/renditions/:kind[?version=]` uses `readRendition`; `/blobs/:sha256/:filename` finds a rendition using that blob on a document within the user's clearance (BLOB_NOT_FOUND 404, FORBIDDEN 403, a malformed sha 400). Non-PDF responses carry `Content-Security-Policy: sandbox` and `nosniff`, so an uploaded HTML/SVG file cannot script the app. Brand assets are resolved only through `brandAsset` (logo, signatures, fonts by weight or by the resolved file name the HTML renderer emits); `/assets/fonts/` is a static mount of `assets/fonts/` only. Previews are served from `<dataDir>/previews/<64-hex token>/preview.(pdf|html|md)`; the token is a content hash, so previews are not clearance-gated beyond the generator's template check.
- **Form encoding.** Field names are dotted paths (`billTo.name`, `items.0.amount`); controls start with `$` (`$brand`, `$action`, `$documentId`, `$force`, `$note`), which no template field name can. Untouched rows of an array are dropped; lists without row columns are a textarea (one entry per line, or JSON); booleans and enums are selects whose empty choice means "default". Blank strings go to resolveFields as is (blank = not provided).
- **Status mapping:** `*_NOT_FOUND` 404, FORBIDDEN 403, `*_DUPLICATE`, `*_CONFLICT`, STATUS_LOCKED, INVALID_STATUS_TRANSITION, NUMBER_CONTENDED 409, TEMPLATE_INVALID/TEMPLATE_SYNTAX 500 (a broken template folder is a server-side problem), everything else 400. Unknown errors are a 500 without internals. New web-only codes: `CSRF_REJECTED` 403, `HOST_REJECTED` 421, `ASSET_NOT_FOUND` 404, `NOT_FOUND` 404.
- **Upload amount** is a decimal (`coerceMoney`) stored as `amountMinor`, with the workspace currency when none is given.
- **`dossier init` seeds**: after copying the example it opens the new workspace once (creating the database) and runs `seedEntities`; `dossier seed` re-runs it.

## 2026-11-24 (brand settings)

- **Validate the candidate against the whole workspace.** `loadWorkspace(home, { files })` takes parsed bodies that replace files on disk (a new `brands/<id>/brand.json` key adds the brand), so a settings save runs the same checks as startup (cross-file: series maps, inheritance, default brand) before anything is written; failures are `WORKSPACE_INVALID` with `details.errors: [{ file, path, message }]` parsed from the WorkspaceError. Saving `series.json` is also refused when a template that loads now would stop loading. Reason: one validator, no drift between startup and the editor. Cost: a hand-broken file elsewhere blocks saves until fixed (the error names it).
- **Write = temp file in the same folder + fsync + rename, then reload.** After the rename `ctx.ws` is reloaded from disk (restoring the old bytes if that fails), `ctx.user.clearance` recomputed, `syncBrands` run and `workspace.write` audited with before/after bodies (truncated with a sha256 above 64 KB). Templates, previews and generation read `ctx.ws` per call, and the image cache is cleared after uploads, so nothing needs a restart. The MCP process notices such saves itself (see MCP below).
- **Forms per section, not raw JSON.** Each section form replaces only its keys in the brand's own file and keeps the rest (layoutProfiles, templateParams, unknown keys). Rows are dotted names (`registrations.0.label`) with one blank row for adding without script; tax rates are a textarea of `label = 0.09` or `label = 9%` lines; palette colours have a "default" box (a colour input always submits a value).

A signature upload to a brand that inherits its signatories copies the inherited list into the brand (arrays inherit whole).

- **No clearance above your own, on effective clearances.** A workspace.json save compares `clearanceFor` before and after for every user (listed before, listed after, and the acting user), so a blank clearance, a removed entry or a newly listed user counts as Confidential. Refused: any user changed to, or newly listed at, a clearance above the acting user's; changing or removing a listed user ranked above the acting user. Lowering, including your own, applies at once. Reason: the editor must not be a way to raise your own access or strip a senior user's; the file stays editable by hand.

Asset uploads are read with a per-route 10 MB multipart limit and a larger file is `ASSET_TOO_LARGE` (413). ## 2026-11-24 (MCP server)

- **One context per MCP process, actor `mcp:<user>`.** `src/mcp.js` opens the workspace as `DOSSIER_USER` (default `mcp`, so an unlisted user gets the default `Confidential` clearance); `openContext` takes an `actor` option so audit rows read `mcp:<user>` while clearance still comes from the workspace user. Tools call services only; the MCP layer adds no rules of its own beyond output shaping (a `usable` flag from `canAccess`, rendition file paths, one-line summaries).
- **Reload on change, checked per call.** `refreshWorkspace(ctx)` (`src/context.js`) compares a fingerprint (path, size, mtime of `workspace.json`, `series.json`, `seeds/entities.json`, every `brands/<id>/brand.json`) with the last load before each tool call and resource read; on a change it loads the workspace and, when `configHash` differs, swaps `ctx.ws`, recomputes clearance and runs `syncBrands`. A workspace that fails to load fails closed: it is remembered in `ctx.wsError` and every tool call and resource read is refused with `WORKSPACE_INVALID` (not re-read until the files change again). Rejected: keeping the previous workspace, because a broken edit could be one that lowers the MCP user's clearance. Rejected: `fs.watch` (unreliable across platforms and editors, needs lifecycle handling) and reloading on every call (parses and validates every brand file per call). The MCP layer caches no database data, so `PRAGMA data_version` is not needed; templates are scanned from disk per call already.
- **Results: JSON text + `structuredContent`, no `outputSchema`.** Tool output shapes are the services' own and evolve with them; declaring output schemas would duplicate them and make the SDK reject results on drift. Errors are `isError: true` with `{ code, message, hint, details }`; `hint` is the service's `details.hint` or a per-code default. SDK-level failures (schema violations `INVALID_INPUT`, unknown tool `TOOL_NOT_FOUND`, anything else `MCP_ERROR`) are routed through the same shape by overriding `McpServer#createToolError`. That method is internal to the SDK, so the SDK is pinned to `~1.32.2`, the server logs to stderr at startup when the method is missing, and the MCP tests fail if an update changes it.
- **Strict tool arguments.** Every `inputSchema` is a `z.strictObject` (`additionalProperties: false`). With raw shapes, zod silently dropped unknown keys, so a misspelled `documentId` on `generate_document` created a new document and used a number instead of regenerating.
- **Clearance is a result filter, not a sandbox.** docs/MCP.md says so. An agent that can read `data/` (blobs, sqlite) sees everything; isolation needs Claude Code to run without read access to the workspace.
- **Lifecycle wording from `TRANSITIONS`.** The `update_status` description and the INVALID_STATUS_TRANSITION hint are built from `domain/status.js`, so they cannot drift.
- **Preview with missing fields is not an error.** `preview_document` returns `ok: false` with `missing`/`errors` (like the web JSON API's body), because it is the step that tells the agent what to ask for; `generate_document` with missing fields is `FIELDS_MISSING`.
- **zod 4 for input schemas.** The SDK (1.32) accepts zod 3.25+ or 4 raw shapes; the repo's zod 4 is used directly.
- **stdout is protocol only.** `main()` redirects `console.log/info/debug` to stderr before anything loads data, logs go to stderr with a `dossier-mcp:` prefix; a test spawns `node src/mcp.js` and checks every stdout line is a JSON-RPC message.

## 2026-11-24 (cache layers)

- **The creation date is part of the render cache key.** A PDF embeds `CreationDate` (and pdfkit's `/ID` is derived from the info dict), so the same inputs rendered at another time are other bytes; serving an older render for a new one would make a hit differ from a fresh render. So the key includes `creationDate`, and the two callers choose it: previews are now dated midnight UTC of the preview's `today` (a draft's date is not meaningful; this makes previews reproducible within a day and lets them hit), finals keep `creationDate` = now (the date the version was made), which means a final only hits when generated again with the same `creationDate` option (tests, scripted regeneration). Rejected: keying finals without the date (a hit would carry an older creation date into a new version), and dating finals by the document date (changes what a filed PDF says).
- **Finals still go through the cache.** One code path for previews and finals; a final's renditions are written to the cache as well as to the blob store (bounded by the LRU size). The resolved values include full entity views (with `documentCount`), so the first regeneration after a document is filed has new values: correct over-keying, not worth special-casing.
- **"Asset files actually used" are recorded, not guessed.** `brandAsset` records `[brandId, key]` lookups in an `AsyncLocalStorage` set while `trackBrandAssets` runs (concurrent renders do not mix). The list is stored per base key (`<base>.assets.json`); a lookup re-resolves each key now (so a brand file that newly shadows an inherited or placeholder file counts) and hashes the file (memoised by size, mtime and inode). Changing a file the render did not use (another signatory's signature) keeps the entry. All asset reads in `src/render` go through `brandAsset`; templates must do the same (docs/TEMPLATES.md).
- **Shared render code hash.** sha256 over every file in `src/render`, `src/templates`, `src/workspace`, `src/domain`, `src/services/generator.js` and `src/paths.js`, computed once per process, plus the pdfkit, fontkit and sharp versions. Broader than strictly needed (an edit to a domain helper empties the cache), never narrower.
- **Memo invalidation by table version, flush on foreign writes.** In-process writes bump per-table versions (applied when the transaction ends, so the memo is bypassed inside a transaction); `PRAGMA data_version` or a changed `ctx.ws.configHash` flushes everything. The template scan reads folders, not tables, so its key also carries a stat fingerprint of the template folders: a template edited on disk is picked up on the next call, as before, without re-reading and validating every folder per call. Raw SQL that bypasses the repo must `repo.bump` the table (two tests that write fixtures with SQL now do).
- **Brand assets are `public`, revalidated unless versioned.** `/assets/brands/:id/logo` names a slot, not content, so `immutable` would keep a replaced logo for a year; it is used only when the URL carries `?v=<12+ hex of the file sha256>` (the settings page does), otherwise `public, no-cache` with the file's ETag (a 304 costs a stat and a memoised hash). The shipped fonts and `/static/` keep the static plugin's ETag with `public, max-age=0`: their names do not change between releases. This departs from the brief's blanket "`/assets/*` immutable", because none of these URLs are content-hashed today.
- **Gated files: `private`, gate before 304.** Blobs are content-addressed (`private, max-age=31536000, immutable`); renditions by document id follow the current version (`private, no-cache`). Both run the clearance check (`readBlobForUser` / `readRendition`) before comparing `If-None-Match`, so a user below the document's clearance gets 403, never 304. A user's own browser may still hold a file after its sensitivity is raised; that copy was already delivered to that user.
- **Everything else is `no-store`.** An `onSend` hook sets it on any reply without a `Cache-Control` (API JSON, pages, redirects, errors), so a new route is uncached unless it opts in.

## 2026-11-24 (legacy import)

- **Identical bytes are one document.** A file whose sha256 is already behind any rendition is "already in the vault" and skipped; a second identical file within one run is a duplicate (the legacy index did the same with md5: "identical copy … not copied again"). This is what makes a re-run import nothing new. Rejected: a new document sharing the blob per path (re-runs would need a path registry, and the legacy tree's copies are copies, not separate documents).
- **Source path on the version, not a new column.** Documents have no free-form attributes; the importer stores `{ "import": { "source_path", "source_folder", "index_note"? } }` as the version's `input_json` and "Imported from <path>" as its note. Adding a documents.attrs column for one importer-only field was not worth a migration. `uploadFile` gained `meta.inputJson` (stored on the version) and an `extracted` argument (text already extracted by the caller, so the importer does not parse a PDF twice).
- **Classification is driven by the routing table and the entity list, never by names in code.** Top-level folders match on the name after the number (configured names, default names, a few generic aliases such as "Team", "Customers", "Suppliers", "Security"; a `<slot> - <leaf>` name like "Vendors - Invoices Received" also gives the leaf), or a group entity already in the entity list. Leaf folders map back to types through `routingConfig` (including `LEAF_MAP` translations and workspace overrides); several types per leaf are narrowed by the parsed number's series (series -> template types for the brand, read with `peekTemplates`, which does not write the registry) and then by type words in the file name. Unrecognised -> `Other`.
- **Client folders:** `<business line>/<client>/<engagement>` by position, except that a first folder naming an existing client (and no business line) is the client. New clients are related to their business line and new engagements to their client only when they have no such relation yet.
- **Imported documents stay Draft.** The lifecycle states record what happened to a document; the importer cannot know whether a legacy file was sent, signed or paid. Set statuses afterwards.
- **Numbers:** file name first (longest hit), then the text (first hit: a document's own number precedes the numbers it cites, e.g. a receipt's invoices). In file names a literal `/` of a pattern matches `-` or `_` (`findNumbers(..., { looseSeparators })` in `domain/numbering.js`); the stored number is rebuilt in the pattern's own form. Counters are seeded with `registerExisting` after the document is filed; a seed that cannot be made (a pattern needing a year without one in the file name) is a warning, not a failure.
- **Dry run reads everything and writes nothing.** It hashes, extracts text, classifies and looks entities up, but creates no entity, counter, blob, document or template registry row; conflicts are predicted from the database plus earlier files of the run. A test compares every table count, the sequences, the last audit id and the blob folder before and after.
- **Per-file failures do not stop an import.** Any error on one file is reported under Skipped with its code; the run goes on.
- **`aliasOf` by name resolves within the entity's kind** (fix of a Task 4 finding): `upsertEntity({ kind, name, aliasOf: 'EISS' })` no longer fails as ambiguous when another kind also uses that name. A numeric `aliasOf` still names an entity by id, and a wrong kind is still INVALID_INPUT.
- **Fix round 1 (review): no way past the Restricted rule.** CSV paths must stay inside the CSV's folder (the import root in index mode): `..` segments, absolute paths elsewhere and files whose folder `realpath` leaves the root are refused as "outside import root"; the file itself is `lstat`ed and symlinks refused; the skip rules run on the path as written and on the path as it resolves (a link to a Restricted folder is still Restricted). A folder named "Restricted" (numbered or not, or "Restricted - …"/"Restricted – …") is skipped at any depth, not only at the top. `src`/`scripts` folders count as code only when they hold `package.json` or `.js`/`.mjs`/`.cjs`/`.py` files, so a "Scripts" folder of documents imports. A source path imported before with other bytes is filed again with a `SOURCE_CHANGED` warning (new document; the old one is not touched). Folder mode skips root `_*.csv` and `*HIERARCHY*.md` as index/spec files and only counts `.DS_Store` files. `renditions.blob_sha256` was already indexed (`renditions_blob`, 001_core), so no migration; a test pins it.
